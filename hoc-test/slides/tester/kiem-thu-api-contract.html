API

API là gì khi kiểm thử

  • API (giao diện lập trình ứng dụng): cách hai phần mềm trao đổi dữ liệu, thường qua yêu cầu HTTP.
  • Mỗi yêu cầu có phương thức (GET, POST), đường dẫn, và nội dung. Mỗi phản hồi có mã trạng thái và dữ liệu.
  • Kiểm API là gửi yêu cầu và kiểm mã trạng thái, cấu trúc dữ liệu, và giá trị trả về.

CONTRACT

Hợp đồng giữa hai bên

  • Contract testing kiểm rằng bên tiêu thụ (consumer) và bên cung cấp (provider) vẫn đồng ý về giao diện: trường nào, kiểu gì, bắt buộc hay không.
  • Bên tiêu thụ viết một mô tả về điều nó cần. Bên cung cấp chạy lại mô tả đó trên bản mới của mình.
  • Nếu bên cung cấp đổi "gia" từ số sang chuỗi, contract test báo lỗi trước khi phát hành.

Giải thích chi tiết

API

  • Là gì: Giao diện để phần mềm trao đổi dữ liệu với nhau, thường qua yêu cầu HTTP.
  • Ví dụ: GET /api/san-pham trả về danh sách sản phẩm dạng JSON.
  • Vì sao quan trọng: Nhiều lỗi nằm ở API, và có thể kiểm mà không cần giao diện.

Mock server

  • Là gì: Máy chủ giả trả về phản hồi định sẵn, dùng khi dịch vụ thật chưa sẵn sàng.
  • Ví dụ: Mock trả về giá sản phẩm 120000 cho mọi mã sản phẩm, để kiểm giỏ hàng.
  • Vì sao quan trọng: Cho phép kiểm sớm, nhưng mock có thể đẹp hơn thật nên cần ghi rõ giả định.

Giải thích chi tiết

Contract testing

  • Là gì: Kiểm rằng hai bên của một giao diện vẫn thống nhất về trường và kiểu dữ liệu.
  • Ví dụ: Bên tiêu thụ cần "gia" là số. Bên cung cấp đổi thành chuỗi: contract đỏ.
  • Vì sao quan trọng: Phát hiện thay đổi phá vỡ hai bên trước khi phát hành.

Consumer và provider

  • Là gì: Consumer là bên tiêu thụ dữ liệu; provider là bên cung cấp dữ liệu qua giao diện.
  • Ví dụ: Ứng dụng đặt hàng là consumer; dịch vụ kho là provider.
  • Vì sao quan trọng: Gọi đúng vai giúp biết ai phải viết contract và ai phải chạy lại kiểm.
